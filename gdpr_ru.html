Краткое изложение.
  • Хранение. Все данные находятся в одном локальном каталоге данных. База данных, хранилище документов, файл конфигурации и временное хранилище ИИ зашифрованы по AES-256 в состоянии покоя. В открытом виде остаются только временные рабочие копии открытых документов, входящая папка сканов, экспортные и исходящие файлы, кратковременный буфер взаимной проверки и, если он включён, диагностический журнал (раздел 8).
  • Внешний ИИ. Вызовы ИИ из приложения возможны только с собственным API-ключом пользователя. Вызовы через центральный маршрутизатор по умолчанию псевдонимизируются и записываются в локальный журнал аудита; намеренные исключения с передачей данных в открытом виде перечислены в 2.3.
  • Согласие. Чат с ИИ, регистрация документов и поиск сведений о лице запрашивают согласие один раз за сеанс или запуск программы; в текстовом редакторе запуск функции ИИ является согласием. Несколько фоновых функций обращаются к облачному ИИ без собственного диалогового окна: сортировка электронной почты, Монитор целостности данных, ежедневная сводка, резюме диалога и проверка Red/Blue Team (раздел 3).
  • Bridge для настольного ИИ. Необязательное дополнение, которое передаёт реальные данные дел поставщику собственного настольного ИИ пользователя после одного диалогового окна согласия за запуск программы (раздел 4.9).
  • Прочие сервисы. Адреса сторон ежедневно геокодируются через OpenStreetMap Nominatim (только адрес, без имён); файл новостей загружается с www.ironstick.legal после запуска и затем каждые шесть часов; никакие данные дел или персональные данные производителю программного обеспечения не передаются (разделы 1 и 7).
  • IRONSTICK SERVER. Необязательный; работает на собственном NAS фирмы внутри её локальной сети, без подключений к интернету. Документы передаются на сервер и хранятся там только как файлы, зашифрованные AES-256; сервер никогда не видит их открытого текста. Рабочее время по делам и события резервного копирования каждого рабочего места видны администратору фирмы (раздел 9).

1. Сфера применения и конечные точки

Внешние вызовы ИИ из приложения направляются тому поставщику, которого автоматический каскад использует в данный момент. Пользователь может настроить до четырёх поставщиков; поставщики, для которых введён ключ, используются в следующем фиксированном порядке, начиная с самого дешёвого: Qwen (Alibaba Cloud) → Kimi (Moonshot AI) → ChatGPT (OpenAI) → Claude (Anthropic). При каждом запуске программы IRONSTICK проверяет, какие из них отвечают. Если поставщик выходит из строя, тот же запрос передаётся следующему. К вышедшему из строя поставщику возвращаются после времени ожидания, зависящего от ошибки; до конца дня он пропускается только в том случае, если его кредит исчерпан или причина неизвестна. Передаваемое содержание идентично у каждого поставщика (начиная с раздела 3: псевдонимизация маршрутизатором, согласие, журнал аудита). Конечные точки:

  • Claude: POST https://api.anthropic.com/v1/messages, собственный API-ключ пользователя.
  • ChatGPT: POST https://api.openai.com/v1/chat/completions, собственный API-ключ пользователя.
  • Qwen: POST https://dashscope-intl.aliyuncs.com/compatible-mode/v1/chat/completions (Alibaba Cloud Model Studio, международный регион), собственный API-ключ пользователя.
  • Kimi: POST https://api.moonshot.ai/v1/chat/completions (Moonshot AI), собственный API-ключ пользователя.

Бесплатные фоновые поставщики (необязательно). Дополнительно пользователь может указать бесплатные предложения Groq, OpenRouter и Mistral. IRONSTICK использует их исключительно для задач, выполняемых в фоновом режиме: сортировки почты, Монитора целостности данных, ежедневной сводки, резюме диалога, распределения по говорящим при транскрипции, получения текстов законов и обзора ситуации. У каждого из этих поставщиков в конфигурации есть собственный переключатель «вкл/выкл»; поставщик используется только в том случае, если указан ключ и его переключатель включён. Для чата, для процессуальных документов и для проверки Red/Blue Team они никогда не используются. Если ни один из них недоступен, работу берёт на себя описанный выше каскад. Псевдонимизация, согласие и журнал аудита определяются соответствующей задачей (раздел 4). Конечные точки:

  • Groq: POST https://api.groq.com/openai/v1/chat/completions, собственный API-ключ пользователя.
  • OpenRouter: POST https://openrouter.ai/api/v1/chat/completions, собственный API-ключ пользователя.
  • Mistral: POST https://api.mistral.ai/v1/chat/completions, собственный API-ключ пользователя.
Бесплатные предложения — указание в конфигурации. В конфигурации под каждым из этих поставщиков указано, что IRONSTICK — если API-ключ сохранён и переключатель включён — использует его для фоновых задач, таких как сводки и сортировка электронной почты, и при этом передаёт данные этому поставщику. Прежде чем включить любого из этих поставщиков, проверьте, предусматривают ли его условия договор об обработке данных, необходимый для обработчиков, и отвечают ли они Вашим профессиональным правилам. Выключенный поставщик не используется.

Для каждого поставщика используются три настраиваемых уровня моделей (малый / средний / большой). Отдельным, необязательным каналом является Bridge для настольного ИИ (раздел 4.9): в этом случае данные поступают в собственный локальный настольный ИИ пользователя (Claude Desktop / Claude Code, ChatGPT Desktop, Qwen Desktop или Kimi Desktop), т. е. поставщику этого ИИ (Anthropic, OpenAI, Alibaba Cloud/Qwen или Moonshot AI/Kimi) в рамках собственной подписки/учётной записи пользователя у этого поставщика. Модули Bridge могут работать параллельно: у каждого настольного ИИ есть своя небольшая программа Bridge, все они подключаются к одной и той же локальной конечной точке в работающем приложении и могут одновременно работать над одним и тем же делом. Никакие данные дел или персональные данные не передаются производителю программного обеспечения. Единственный контакт с производителем — простая загрузка файла новостей с www.ironstick.legal (после запуска и затем каждые шесть часов, раздел 7), который не содержит никаких данных, кроме самого технического соединения. IRONSTICK SERVER (раздел 9) этого не меняет: он эксплуатируется самой юридической фирмой, на собственном оборудовании фирмы, внутри собственной сети фирмы — он никогда не связывается с производителем и никогда не связывается ни с каким поставщиком ИИ.

Главным выключателем является собственный доступ пользователя. Внешняя обработка ИИ из приложения существует лишь в том случае, если пользователь открыл собственную учётную запись у поставщика ИИ и ввёл собственный ключ доступа в конфигурации. Если не настроен ни один поставщик, никакой внешний вызов ИИ из приложения вообще невозможен — каждая функция, описанная в разделе 4, в этом случае остаётся локальной или просто недоступна. Эта учётная запись представляет собой прямой договор между пользователем и поставщиком; IRONSTICK не является его стороной. То же относится к Bridge для настольного ИИ, который требует собственной подписки/учётной записи пользователя у выбранного поставщика настольного ИИ (Anthropic, OpenAI, Alibaba Cloud/Qwen или Moonshot AI/Kimi). Документы, помеченные как секретные, исключены из инструментов Bridge и чата, из пакета инструкций для ИИ и из любых генерируемых результатов (вложения, досье, экспорт); их обработка при регистрации документов следует осознанному выбору пользователя в момент регистрации (раздел 4.1).

Полностью локально (ничего не покидает компьютер): извлечение текста и OCR, детерминированный локальный уровень чата, глобальный поиск, радар релевантности, анализ цепочек писем, генерация досье/PDF, локальный проход средства поиска для затемнения, распознавание речи (транскрипция записей) и формирование пакета инструкций для ИИ.

2. Слой псевдонимизации

Каждый вызов из приложения через центральный маршрутизатор ИИ по умолчанию псевдонимизируется: идентификаторы в исходящем тексте заменяются токенами, а ответ локально восстанавливается. Если псевдонимизатор не удаётся построить полностью, ничего не отправляется. Исключения перечислены в 2.3. Таблица соответствия существует только в памяти, по одной новой таблице соответствия на каждую операцию; она никогда не сохраняется.

2.1 Что заменяется

2.2 Что намеренно остаётся настоящим

  • Даты, время и денежные суммы — они нужны в неизменном виде для юридического анализа.
  • Наименования учреждений (суды, органы власти) — их нет в словаре, и они являются публичными органами.
  • Третьи лица без собственной записи — свидетели, врачи, адвокаты, судьи или компании, которые не внесены как запись клиента, лица или дела; того, кого следует заменять токеном, достаточно просто внести как лицо.
  • Адреса лиц, не являющихся клиентами — токеном заменяется сохранённый адрес клиента.
  • Всё фактическое содержание документов (утверждения, диагнозы, изложение событий) — заменяются только идентификаторы, а не сама история.

2.3 Намеренные исключения с передачей настоящих имён

  • Веб-поиск сведений о лице (этап 1) и автозаполнение форм для лиц / учреждений: веб-поиск по $PARTEI_A$ бессмыслен, поэтому настоящее имя отправляется намеренно.
  • ИИ-средство поиска для затемнения: оно получает текст, который уже был затемнён локально, и должно ответить настоящими именами найденных им неизвестных третьих лиц — для этой единственной цели псевдонимизация отключена.
  • Предварительная обработка для чтения вслух (TTS): см. 4.6 — предложения передаются в открытом виде.
  • Bridge для настольного ИИ: необработанные данные намеренно (раздел 4.9).

3. Моменты согласия и журнал аудита

Вызовы, проходящие через центральный маршрутизатор, требуют согласия и протоколируются: каждый раунд модели записывает строку в локальную таблицу аудита с полным запросом и ответом в той форме с токенами, в которой они фактически покинули компьютер; отклонённые или заблокированные попытки протоколируются без содержания. Если функция запрашивает согласие, диалоговое окно указывает уровень модели и приблизительный объём запроса, и одно одобрение распространяется на текущий сеанс экрана (для регистрации документов: на текущий запуск программы).

Потоки через маршрутизатор без собственного диалогового окна согласия: сортировка электронной почты (как в фоновом режиме, так и при ручной загрузке на экране электронной почты, раздел 4.2), аналитический прогон Монитора целостности данных (4.5), ежедневная сводка (4.4a), резюме диалога чата через API и проверка Red/Blue Team (4.7), а также ИИ-средство поиска для затемнения (включение его переключателя является согласием). Эти потоки тем не менее псевдонимизируются (за исключением предусмотренных ответов средства поиска для затемнения с настоящими именами) и тем не менее подлежат аудиту.
Потоки в обход маршрутизатора: функции ИИ текстового редактора, предварительная обработка для чтения вслух и корректирующий вызов ИИ File→Markdown обращаются к API напрямую. Они псевдонимизируются (исключение: чтение вслух), но не показывают собственного диалогового окна согласия и не записывают строк в журнал аудита. Использование пользователем этих функций (нажатие кнопки ИИ, запуск генерации, запуск чтения вслух при включённом переключателе ИИ) является моментом согласия.

4. Потоки данных по отдельным сценариям использования

4.1 Регистрация документов

Извлечение текста и OCR выполняются локально. Если настроен API-ключ, IRONSTICK запрашивает согласие один раз за запуск программы, после чего выполняется до четырёх типов вызовов (все псевдонимизированы, все подлежат аудиту):

  • Определение основного документа (малый уровень): фрагменты необработанного текста OCR — только для сканов низкого качества.
  • Исправление OCR (малый уровень): ограниченный фрагмент текста документа.
  • Классификация (средний уровень): ограниченный фрагмент текста документа, плюс системные списки: полный список дел (номер дела, имя клиента, противная сторона — заменены токенами), пул известных имён (заменены токенами), а также списки кодов типов учреждений и типов документов (метки без замены токенами). Резервный вариант: малый уровень, без списков.
  • Контекстуализация при сохранении (малый уровень): метаданные документа и полный текст ограниченной длины, плюс индексная строка (ID, дата, заголовок) каждого активного элемента доказательств того же клиента — служит для обоснования перекрёстных ссылок. Выполняется также для документов, помеченных как секретные (осознанное решение пользователя).

4.2 Монитор почты (сортировка)

Отнесение к делу выполняется локально и без ИИ. Новая почта загружается в фоновом режиме при запуске и затем каждые пять минут. Письмо, дело которого локальное распознавание уже определяет (номер дела, номер письма, номер клиента или ссылка на собственное заявление), не вызывает обращения к ИИ. Для каждого другого письма срочность оценивает один вызов малого уровня, содержащий ровно: имя и адрес отправителя, тему и сохранённый фрагмент предпросмотра в виде простого текста (жёстко ограниченный) — никогда не полный текст письма, никаких вложений и никакого списка дел. Ответ: приоритет и обоснование. Если включены бесплатные фоновые поставщики (раздел 1), этот вызов может выполняться через них. Диалоговое окно согласия не показывается ни в фоновом режиме, ни при ручной загрузке на экране электронной почты: сортировка выполняется автоматически, как только настроены почтовая учётная запись и поставщик ИИ. Данные псевдонимизируются и подлежат аудиту.

Никаких пикселей отслеживания. Открытие письма в мониторе никогда не приводит к обращению к серверу отправителя: изображения, на которые ссылается интернет-адрес (включая невидимые пиксели отслеживания), не загружаются и отображаются как заполнители с уведомлением, поэтому отправитель не может узнать, когда, как часто или с какого адреса письмо было прочитано. Отображаются только изображения, встроенные в само письмо.

4.3 Анализ лица (веб-поиск)

Три этапа после согласия, даваемого один раз за сеанс:

  • Этап 1 — поиск: поисковые системы опрашиваются напрямую с компьютера пользователя; дополнительно вызывается серверный инструмент веб-поиска поставщика с настоящим именем лица в открытом виде (неизбежно для поиска; протоколируется в открытом виде).
  • Этап 2 — резюме страниц (средний уровень): для каждой страницы — имя лица (заменено токеном), URL и ограниченный фрагмент содержимого страницы.
  • Этап 3 — синтез профиля (большой уровень): имя и город (заменены токенами) плюс собранные тексты страниц ограниченной длины по каждому источнику.

Результат сохраняется локально с оценкой достоверности «не подтверждено». Связанные с этим кнопки автозаполнения в формах лиц/учреждений также отправляют введённое имя в открытом виде (задокументированное исключение).

4.3a Проверка стороны по открытым источникам

Проверка стороны по открытым источникам представляет собой фиксированную процедуру, которую приложение выполняет самостоятельно, когда подключённый ИИ вызывает её с указанием имени, города, района, страны и вида стороны (физическое лицо или юридическое лицо):

  • Материалы дел: полнотекстовый поиск имени по локальной базе данных — исключительно локально, ничего не покидает компьютер.
  • Интернет: фиксированный список поисковых запросов отправляется в публичные поисковые системы Google, DuckDuckGo и Qwant. Каждый запрос состоит из поискового термина на языке страны стороны плюс настоящего имени стороны в открытом виде и, для некоторых запросов, города или района (неизбежно для поиска). Никакое содержание дел, клиентов или документов не передаётся. Поисковые системы видят эти запросы так же, как запросы любого пользователя браузера.

Результат возвращается вызывающему ИИ в виде подготовленного, непроверенного профиля. Ничего не записывается в основные данные: каждая находка проходит контрольный шлюз Монитора целостности данных (раздел 4.5) и принимается только тогда, когда пользователь её подтверждает. Оцениваются только общедоступные источники.

4.4 Дневной протокол

Сам экран работает локально. При импорте текста в свободной форме сначала выполняется локальный синтаксический анализатор; только если маркер формата дневного протокола не найден, резервная функция ИИ нормализует необработанный текст: вставленный текст отправляется полностью, малый уровень, с согласием, псевдонимизированно, с аудитом. Сохранённые записи дневного протокола покидают компьютер только как результаты инструментов чата или Bridge для настольного ИИ (ограниченные выдержки) либо в составе пакета инструкций для ИИ (раздел 5).

4.4a Ежедневная сводка

При первом запуске программы за день (Windows) IRONSTICK готовит в фоновом режиме устную ежедневную сводку — уже во время запуска и до того, как окно сводки спросит, хочет ли пользователь её прослушать. Текст сводки — количество сроков, судебные заседания на сегодня и на завтра с номером дела, именем клиента, городом и судом, а также названия сегодняшних встреч — отправляется один раз (малый уровень) облачному ИИ, который переписывает его в виде разговорной речи на системном языке. Псевдонимизация через маршрутизатор, аудит, без диалогового окна согласия. Если включены бесплатные фоновые поставщики (раздел 1), этот вызов может выполняться через них. Если доступного поставщика нет, используется текст, собранный локально.

4.5 Монитор целостности данных

Фаза 1 (электронная почта ↔ основные данные) полностью детерминирована. Фаза 2 отправляет на каждый новый входящий документ один вызов малого уровня (псевдонимизированно, с аудитом, без диалогового окна), содержащий: очищенные от дубликатов фрагменты контактных областей (короткие фрагменты вокруг адресных, телефонных и налоговых данных) из полного текста этого документа, имена сторон этого документа и его дела, а также для каждой стороны имена возможных совпадений из сохранённых основных данных (заменены токенами, если они есть в словаре; наименования учреждений в открытом виде). Контактные данные и идентификационные номера из сохранённых основных данных не передаются. Если включены бесплатные фоновые поставщики (раздел 1), этот вызов может выполняться через них. Ответ всегда становится лишь предложением, которое пользователь должен принять в мониторе.

4.6 Текстовый редактор (помощь ИИ в тексте)

  • Переработка выделенного фрагмента: выделенное предложение/абзац/раздел (с разметкой) плюс фрагмент документа в качестве контекста и указание пользователя — средний уровень, псевдонимизированно.
  • Структура/оглавление: фактически весь документ в виде индексированного списка строк (длинные строки усечены), ограниченной длины — средний уровень, псевдонимизированно.
  • Предварительная обработка для чтения вслух: при чтении документа вслух каждое предложение отдельно отправляется на малый уровень в открытом виде для раскрытия сокращений и чисел — без псевдонимизации (идентификационные номера должны вернуться без изменений, чтобы быть прочитанными правильно). Штампы файлов и ссылочные маркеры предварительно удаляются локально. Запуск чтения вслух является моментом согласия.
Ни один из вызовов текстового редактора не показывает отдельного диалогового окна согласия и не записывает строк в журнал аудита (обход маршрутизатора, раздел 3).

4.7 Проверка Red/Blue Team и резюме диалога (API)

К составлению документов относятся ещё два потока API. Red/Blue Team: если пользователь включил эту функцию для активного поставщика (переключатель рядом с API-ключом; требуется сохранённый ключ), каждый официальный документ, передаваемый через диалоговое окно выдачи, — как из чата в приложении, так и из Bridge для настольного ИИ, — ещё раз прочитывается тем же поставщиком в роли представителя противной стороны в отдельном проходе проверки (средний уровень). Передаются: текст проекта, дата и юрисдикция дела; псевдонимизированно через маршрутизатор и с аудитом, как и любой вызов через маршрутизатор; без диалогового окна согласия — переключатель является согласием; отчёт проверяющего прилагается для пользователя. Проверка Red/Blue Team никогда не выполняется через бесплатных фоновых поставщиков (раздел 1). Резюме диалога: в длительных сеансах чата через API более ранняя часть диалога (только вопросы пользователя и окончательные ответы модели, никогда не результаты инструментов) сжимается активным поставщиком (малый уровень, в фоновом режиме, без собственного диалогового окна согласия) в краткое резюме, которое заменяет необработанную историю; оно хранится в зашифрованном виде во временном хранилище и каждый раз перезаписывается. Данные псевдонимизируются и подлежат аудиту. Если включены бесплатные фоновые поставщики (раздел 1), резюме может создаваться через них.

4.8 Чат с ИИ (внешний, API)

Согласие один раз за сеанс чата; средний уровень с автоматической эскалацией на большой уровень (в этом случае весь контекст отправляется повторно); псевдонимизированно; каждый раунд подлежит аудиту. Каждый ход передаёт: системный промпт (статичные правила), текущий контекст графического интерфейса (текущий экран, открытое дело/клиент, включая имя клиента, — заменено токеном), до 10 записей памяти ИИ открытого клиента, последнюю часть диалога плюс резюме более ранних ходов (4.7) и список временных файлов чата. Каждый инструмент, вызываемый моделью, возвращает свой результат в диалог API — включая полные тексты документов (более объёмные результаты помещаются в зашифрованное временное хранилище), тексты электронных писем и выдержки из дневного протокола. Чат использует тот же уровень инструментов и те же шлюзы выдачи, что и Bridge для настольного ИИ (4.9): проверку процессуальных документов, Red/Blue Team (4.7) и передачу через диалоговое окно экспорта — то, что покидает систему, является шаблоном, готовым к подаче. Локальный уровень чата отвечает на рутинные запросы без какой-либо передачи данных.

Две вспомогательные функции заслуживают отдельного упоминания. Запрос погоды получает текущие данные о погоде для названного места от сервиса Open-Meteo, не являющегося LLM (раздел 7), — этому сервису передаётся только название места / его координаты, никогда не данные дел или лиц. Запрос местоположения отвечает исключительно на основе последнего локально сохранённого снимка безопасности (раздел 8): запрос ИИ не инициирует нового внешнего запроса — он лишь считывает то, что уже находится на диске. Как и в случае любого инструмента, то, что эти функции возвращают, поступает обратно в диалог с ИИ, т. е. к поставщику ИИ.

4.9 Bridge для настольного ИИ (необязательные дополнительные модули)

Каждый доступ к настольному ИИ является необязательным модулем, приобретаемым отдельно. Он существует только там, где юридическая фирма приобрела и установила соответствующий модуль Bridge; при отсутствии какого-либо модуля раздел Bridge в конфигурации остаётся заблокированным, локальная конечная точка никогда не запускается, и ни один из потоков, описанных в настоящем разделе, не может возникнуть. Модули Bridge доступны для Claude Desktop/Claude Code, ChatGPT Desktop, Qwen Desktop и Kimi Desktop; у каждого есть своя небольшая программа Bridge, и все они подключаются к одной и той же локальной конечной точке в работающем приложении. Описанные ниже потоки данных идентичны для всех; различается лишь поставщик-получатель.

Этот канал передаёт реальные данные дел. В этом и состоит его назначение: собственный сеанс пользователя с настольным ИИ составляет шаблоны, готовые к подаче, и поэтому нуждается в настоящих именах и номерах.
  • Настольный ИИ (Claude Desktop/Code, ChatGPT Desktop, Qwen Desktop или Kimi Desktop) подключается к работающему приложению через свою программу Bridge; это соединение остаётся на компьютере. В интернет обращаются только инструменты веб-поиска, чтения страниц и реестров.
  • Сайты с проверкой доступа. Если сайт требует подтверждения, прежде чем открыть своё содержимое, IRONSTICK открывает страницу в отдельном окне; пользователь сам подтверждает там. Содержимое страницы затем читает настольный ИИ — оно, как и любой другой результат инструмента, поступает его поставщику.
  • Первый доступ к данным со стороны любого настольного ИИ за запуск программы открывает одно блокирующее диалоговое окно согласия. Одобрение открывает доступ для всех настольных ИИ до конца запуска программы; отказ временно блокирует их всех.
  • Более 200 инструментов предоставляют доступ к хроникам, полным текстам, электронным письмам, дневным протоколам, срокам, основным данным, целым делам (по частям) и форматам вывода; документы, помеченные как секретные, исключены. Изменения основных данных, хроники, календаря, памяти ИИ, полных текстов и правовой библиотеки вступают в силу только после того, как пользователь одобрит их в форме IRONSTICK, диалоговом окне или в Мониторе целостности данных: предложения по основным данным и связям попадают в монитор; предложенные ИИ изменения привязанных к делу заметок с инструкциями для ИИ отображаются в виде красно-зелёного сравнения и применяются только после того, как пользователь явно их примет; записи хроники никогда не записываются ИИ — он лишь предварительно заполняет форму регистрации, которую пользователь дополняет и сохраняет сам; а восстановленный ИИ полный текст документа (повторное OCR-сканирование) заменяет сохранённый полный текст только после того, как пользователь увидел полный текст в диалоговом окне подтверждения и сохранил его. Без такого диалогового окна ИИ записывает только в собственные рабочие области: зашифрованное временное хранилище, дневной протокол по просьбе пользователя и собственную оценку дела после детерминированных проверок. Теги и сообщения в чате фирмы требуют подтверждения пользователя в чате. В деле, на которое оформлена подписка от коллеги, ИИ может закрепить заметку, которая через IRONSTICK SERVER передаётся владельцу дела и всем подписчикам (раздел 9). Передача в текстовый редактор и выдача файлов являются явными действиями пользователя; навигация — только при наличии отдельного разрешения.
  • Восстановление путём повторного OCR-сканирования (локально) и передача PDF (по инициативе пользователя). Если сохранённый полный текст усечён или испорчен старым прогоном OCR, ИИ может запросить новое сканирование: пользователь выбирает страницы, повторное сканирование выполняется локально (без нового внешнего получателя), и обе версии текста помещаются в локальное временное хранилище; всё, что ИИ из них считывает, поступает к его поставщику, как и любой другой результат инструмента. В качестве самой крайней меры — только после такого повторного сканирования и только в жёстких пределах, обеспечиваемых модулем Bridge, — ИИ может попросить пользователя передать ему исходный PDF-файл: IRONSTICK лишь открывает запись; пользователь сам сохраняет PDF с помощью значка скрепки и перетаскивает его в чат настольного ИИ. Тем самым документ передаётся в виде файла (включая штампы, подписи и изображения) поставщику этого ИИ — это происходит исключительно в результате собственного осознанного действия пользователя, никогда автоматически, а документы, помеченные как секретные, с самого начала исключены из всего канала повторного сканирования.
  • Локальное временное хранилище ИИ (минимизация данных). Объёмные результаты инструментов могут помещаться в локальный зашифрованный временный файл и обрабатываться там вообще без передачи поставщику ИИ. Полные выгрузки дел для ИИ и обзор начала сеанса, формируемый одним вызовом, также записываются непосредственно в это локальное хранилище; к поставщику ИИ поступают только те части, которые ИИ затем считывает. Временное хранилище находится внутри папки данных и сохраняется между сеансами (оно является рабочим контекстом ИИ); неиспользуемые файлы удаляются автоматически, и никакого нового внешнего получателя не возникает.
  • Временное хранилище зашифровано. Каждый файл во временном хранилище зашифрован в состоянии покоя по AES-256; файлы покидают хранилище только через диалоговое окно экспорта IRONSTICK, никогда не в папку загрузок. База данных, хранилище документов, файл конфигурации и временное хранилище таким образом все зашифрованы по AES-256 в состоянии покоя. Временные рабочие копии открытых документов (очищаются при каждом запуске и при завершении работы), кратковременный буфер взаимной проверки, входящая папка сканов, экспортные и исходящие файлы остаются в открытом виде (раздел 8).
  • Результаты инструментов доставляются в клиент настольного ИИ пользователя, а оттуда его поставщику: Anthropic для Claude (в рамках подписки пользователя на Claude и условий Anthropic), OpenAI для ChatGPT (в рамках подписки пользователя на ChatGPT и условий OpenAI), Alibaba Cloud/Qwen для Qwen Desktop (в рамках учётной записи пользователя в Qwen и условий Qwen) или Moonshot AI для Kimi Desktop (в рамках учётной записи пользователя в Kimi и условий Moonshot AI). IRONSTICK не записывает строк журнала аудита для трафика Bridge; в верхней панели отображается по одному пульсирующему логотипу на каждый активный ИИ (знак Claude, знак ChatGPT, знак Qwen, знак Kimi) — одновременный доступ возможен, и каждый из них сигнализируется отдельно. Каждая программа Bridge ведёт рядом с собой локальный журнал с временем, именем инструмента, успехом/неудачей и объёмом ответа, но никогда не с содержанием. Второй, более подробный диагностический журнал в папке данных по умолчанию выключен; если его включить для устранения неполадок, он может содержать параметры вызовов (среди которых могут быть имена) в открытом виде и автоматически усекается. Ни один из журналов никуда не передаётся.
  • Общая память ИИ хранит локально обобщённые выводы (привязанные к клиенту или делу). ИИ может предложить сохранить, изменить или удалить запись; каждое изменение вступает в силу только после одобрения пользователем. Записи, связанные с делом, никогда не удаляются автоматически; записи без дела удаляются через год без использования. Содержание памяти видно каждому каналу ИИ и передаётся всякий раз, когда эти каналы его считывают.
  • Взаимная проверка между настольными ИИ осуществляется через IRONSTICK, а не напрямую между поставщиками: один ИИ оставляет результат работы (например, проект) в локальном, кратковременном буфере обмена (простые файлы на компьютере пользователя, удаляемые при закрытии задачи и полностью стираемые при каждом перезапуске приложения) вместе с заметкой к задаче; другой ИИ считывает его, когда пользователь даёт ему такое указание. Это не создаёт нового внешнего получателя — всё, что считывает проверяющий ИИ, передаётся его собственному поставщику точно так же, как и любой другой результат инструмента выше, на условиях этого поставщика. Поставщики никогда не обмениваются данными напрямую; то, что считывает проверяющий ИИ, поступает только его собственному поставщику.

4.10 Транскрипция аудио (распределение по говорящим)

Распознавание речи выполняется полностью локально; сама запись никогда не покидает компьютер. Если пользователь указал более одного говорящего, ИИ затем распределяет распознанные строки по говорящим: по частям (средний уровень) распознанный текст, плюс уже распределённые строки как контекст и число говорящих. Вызовы идут через маршрутизатор — псевдонимизированно, при условии согласия, с записью в журнал аудита. Ответ не должен изменять текст: каждая строка сверяется с распознанным текстом; если блок не удаётся, транскрипция принимается без распределения по говорящим. При одном говорящем вызова ИИ не происходит. Если включены бесплатные фоновые поставщики (раздел 1), эти вызовы могут выполняться через них.

7. Внешние сервисы, не являющиеся LLM (для полноты картины)

Независимо от какой-либо LLM, следующие функции обращаются к внешним сервисам с минимально необходимыми данными: проверка номеров (EU VIES, EORI, GLEIF, торговые реестры — проверяемый номер), прямые веб-запросы поиска лиц (имя), IMAP (Ваш почтовый сервер) и необязательный экспорт в Google Drive (экспортируемые файлы). Ни один из них не затрагивает поставщика ИИ.

К следующим сервисам обращения идут в фоновом режиме или с такими же минимальными данными:

  • OpenStreetMap Nominatim (геокодирование адресов) — раз в сутки фоновое задание обрабатывает лиц и компании в записях сторон, у которых указан адрес или город, и отправляет в Nominatim улицу, район, город и страну (никогда не имя), чтобы разместить их на карте; уже размещённый адрес отправляется повторно только при изменении, а не найденный — повторно проверяется после периода ожидания. Название места для запроса погоды геокодируется таким же образом. Диалогового окна согласия нет; координаты хранятся локально.
  • ipwho.is (геолокация по IP) — один раз при каждом запуске программы, в рамках локального снимка безопасности (раздел 8), IRONSTICK запрашивает у этого сервиса публичный IP-адрес компьютера и приблизительное местоположение (город, страна, интернет-провайдер). Запрос не содержит полезной нагрузки; сервис получает публичный IP-адрес, с которого поступает запрос. Ответ хранится исключительно локально и больше никуда не передаётся.
  • Open-Meteo (погода) — по запросу функция ИИ для запроса погоды (раздел 4.8) запрашивает текущие данные о погоде для названного места; ежедневная сводка делает то же для города, указанного в конфигурации, если включён её необязательный режим со ссылкой на погоду. Передаются только координаты места — никогда данные дел, клиентов или лиц.
  • www.ironstick.legal (файл новостей) — после ввода кода доступа и затем каждые шесть часов приложение загружает с сайта производителя программного обеспечения файл новостей с уведомлениями и предупреждениями, а также любое изображение, на которое он ссылается. Запрос не содержит данных; как и любой веб-сервер, сервер производителя видит IP-адрес и время запроса.

Ни один из этих сервисов не затрагивает поставщика ИИ.

8. Локальное хранение, целостность и контроль со стороны пользователя

Независимо от описанных выше каналов ИИ, в отношении всех данных, хранящихся в IRONSTICK, действует следующее:

  • Исключительно локальное хранение. Весь массив данных — база данных, файлы документов, медиафайлы, транскрипты, конфигурация — находится в едином каталоге данных по пути, определяемому пользователем. IRONSTICK не требует облачной учётной записи, и ни одна функция не отправляет данные пользователя производителю (единственный контакт с производителем — загрузка новостей, раздел 7). Если юридическая фирма эксплуатирует необязательный IRONSTICK SERVER (раздел 9), этот сервер также является собственным устройством фирмы в собственной сети фирмы — в отношении доступа производителя ничего не меняется.
  • База данных зашифрована в состоянии покоя (AES-256). База данных — реестр клиентов, дел, хроники, электронных писем, сроков, текстов транскриптов и памяти ИИ — хранится в зашифрованном по AES-256 виде, каждая страница по отдельности и с печатью целостности для каждой страницы. Ключ формируется приложением во время выполнения и никогда не записывается на диск или в конфигурацию, поэтому файл базы данных, скопированный с запоминающего устройства или из архива резервной копии, без IRONSTICK прочитать невозможно. Это техническая мера по смыслу ст. 32 GDPR, которая действует без какой-либо настройки пользователем и не может быть отключена.
  • Документы зашифрованы в состоянии покоя (AES-256). Хранилище документов — исходные PDF, сканы, изображения, аудио- и транскрипт-файлы — зашифровано тем же способом, файл за файлом, с печатью целостности, которая обнаруживает изменения. Чтение осуществляется через единый шлюз, который расшифровывает запрошенный файл во временную рабочую копию и удаляет эти копии при закрытии или запуске приложения. Резервные копии и пакеты дел содержат документы в зашифрованном виде.
  • Что остаётся в открытом виде. Помимо рабочих копий текущего сеанса и экспорта: сканы, ожидающие во входящей папке сканов до регистрации; кратковременный буфер взаимной проверки между настольными ИИ (раздел 4.9, удаляется при закрытии задачи и стирается при каждом запуске); и, только если он включён, подробный диагностический журнал Bridge (раздел 4.9).
  • Контроль доступа при запуске (TOTP). После того как лицензионный ключ принят, приложение не показывает ничего, кроме запроса кода, пока пользователь не введёт текущий шестизначный одноразовый код на основе времени из приложения-аутентификатора (RFC 6238). Секрет, лежащий в основе кодов, никогда не записывается на диск; сохраняется лишь несекретный отпечаток подтверждённой настройки, чтобы QR-код снова отображался после смены ключа. Повторный ввод неверных кодов влечёт возрастающее время ожидания. Модули Bridge для настольного ИИ не получают данных дел, пока приложение заблокировано. Файл конфигурации (API-ключи, учётные данные электронной почты, доступ к серверу) хранится в зашифрованном по AES-256 виде тем же механизмом, что и документы, и расшифровывается только в памяти.
  • Место хранения под контролем пользователя. Путь к данным выбирается при установке и может быть изменён в любое время — в том числе на съёмный носитель, например зашифрованный USB-накопитель или зашифрованный внешний диск. Приложение просто следует настроенному местоположению; шифрование носителя (например, средствами шифрования дисков операционной системы) находится в руках пользователя и рекомендуется для переносных носителей. Сетевые диски и папки, синхронизируемые с облаком (OneDrive, Google Drive, Dropbox, iCloud, Box, pCloud, MEGA), в качестве места хранения данных отклоняются. При смене места хранения в конфигурации IRONSTICK проверяет цель на соответствие этим правилам; копирование выполняется со сверкой контрольных сумм, переключение — только после успешной проверки, а старая папка сохраняется под другим именем.
  • Синхронизация устройств без какого-либо облака. Необязательная синхронизация Windows ↔ планшет Android осуществляется через прямое USB-кабельное соединение — никакой сторонний сервис не задействован, передачи проверяются контрольными суммами, а перед заменой базы данных создаётся обязательная резервная копия. Документы, помеченные как секретные, никогда вообще не передаются на планшет.
  • Снимок безопасности при запуске (локальный журнал входов). При каждом запуске программы IRONSTICK в фоновом режиме фиксирует снимок компьютера, на котором она работает: имя хоста, операционную систему, ОЗУ/ЦП, локальный IP-адрес, браузер по умолчанию, обнаруженные им работающие средства удалённого доступа и производную оценку безопасности — плюс, один раз за запуск, публичный IP-адрес и приблизительное местоположение (город, страна, интернет-провайдер), полученные от сервиса геолокации по IP ipwho.is (раздел 7). Снимок хранится исключительно локально в базе данных и никуда не передаётся. Срок хранения автоматически ограничен максимум 6 месяцами и максимум 1 000 записей (ежедневная очистка), и пользователь может в любое время просмотреть журнал в конфигураторе (карточка «Журнал входов»).
  • Отпечатки целостности для каждого зарегистрированного файла. В момент регистрации каждый сохраняемый файл получает криптографический отпечаток содержимого (SHA-256 для документов и медиафайлов; унаследованный отпечаток MD5 для аудиофайлов транскриптов), записываемый в базу данных рядом с записью. Поэтому любое последующее изменение сохранённого файла может быть обнаружено путём сравнения файла с его записанным отпечатком, а экспорт для e-discovery (EDRM) содержит эти отпечатки, чтобы получатели могли независимо проверить файлы. Благодаря этому любая манипуляция становится очевидной и доказуемой.
  • Резервные копии по усмотрению пользователя. Встроенная функция резервного копирования записывает полную копию данных (полная резервная копия или резервная копия только данных) в виде единого ZIP-архива в любое выбранное пользователем место назначения и по запросу выполняет восстановление из такого архива. Как часто создаются резервные копии, где они хранятся, как долго они сохраняются и шифруются ли архивы дополнительно — полностью на усмотрение пользователя. Внутри каждого архива база данных, документы, конфигурация и временное хранилище ИИ в любом случае зашифрованы по AES-256; без изменений включаются только сканы, всё ещё ожидающие во входящей папке сканов — IRONSTICK не устанавливает никакого графика и никуда не передаёт резервные копии.
  • Сгенерированные документы принадлежат пользователю. Пользователь может в любое время генерировать документы — процессуальные документы, письма, досье, списки, экспорт — и загружать их: они записываются в локальную папку «Документы» или, если пользователь явно выбирает Google Drive в качестве места назначения, в собственную учётную запись Google Drive пользователя. Что происходит со сгенерированным документом после этого — печать, подача в суд, отправка по электронной почте, загрузка в любой сервис, предоставление третьим лицам, — решает исключительно пользователь.
